## Problem

Every hover transition in LUX uses `--ease-standard`:

```css
/* app/tokens.css ~line 323 (generated — do NOT edit this file) */
--ease-standard: cubic-bezier(0.2, 0, 0, 1);
```

That is a strong decelerate, the right curve for something **entering and settling**. On a hover it is wrong, because it front-loads the change. Measured in the browser by solving the bezier:

| share of duration elapsed | `--ease-standard` progress | target `ease` progress |
| --- | --- | --- |
| 10% | 16% | 9% |
| 20% | **50%** | 30% |
| 30% | 69% | 51% |
| 50% | 88% | 80% |
| 70% | 96% | 94% |

Half of every hover lands in the first fifth of its duration. On the 120ms `duration/fast` that most hovers use, 50% of the dim happens in **24ms**, about one or two frames. That reads as a snap followed by a tail nobody sees. Hover-out has the same shape, so leaving snaps too.

**Proof that duration is not the lever.** Earlier on 15 Sep 2026 the selfie shutter was lengthened from `duration/fast` to `duration/slow` to "make the hover smooth", and the user still flagged it. At 320ms it is 50% dimmed after 64ms and 88% after 160ms. The longer duration only stretched the invisible tail.

```css
/* features/my-skin/components/SelfieSheet.module.css — current (working tree) */
.shutter {
  …
  /* ⚠️ `duration/slow`, asked for directly 15 Sep 2026 ("make the hover
     smooth") — the same change as CameraCapture.module.css's shutter */
  transition: opacity var(--duration-slow) var(--ease-standard);
}
```

The rule for hover and colour change is `ease`, which spreads the change across the duration instead of spending it at the start.

## Target

1. A new hand-authored token on `:root` in `app/globals.css`:

   ```css
   --ease-hover: cubic-bezier(0.25, 0.1, 0.25, 1);
   ```

   This is exactly CSS `ease`, written out so it is a token.
2. Every transition entry whose **only** job is a hover response swaps `var(--ease-standard)` → `var(--ease-hover)`. **Durations do not change**: 120 / 200 / 320 / 400 all stay. With a curve that does not front-load, those numbers finally do what they say.
3. Transitions shared with selection, press, entrance or state changes keep `--ease-standard`. See Boundaries.

⚠️ **Why not `--ease-breathe`** (`cubic-bezier(0.37, 0, 0.63, 1)`, already in `tokens.css`): it is a symmetric sine. It is only 9% done at 20% of the duration, so the start of the hover, the moment the user is watching, would feel late. It is also named for the orb's breathing.

## Repo conventions to follow

- `app/tokens.css` is generated from Figma. Hand-authored tokens go on `:root` in `app/globals.css` as their own commented block, each flagged `⚠️ NOT IN FIGMA`. Exemplar (working tree, ~line 550):

  ```css
     … same split `text/on-data` vs `surface/data` already draws. Raise the pair in
     Figma rather than darkening the fill.
     ========================================================================== */

  :root {
    --color-text-success-ink: #46664f;
  }
  ```

- ⚠️ `animation-timing-function: var(--ease-*)` inside `@keyframes` fails silently (`globals.css` documents this). This plan touches **transitions only**, where `var()` works.
- Every `:hover` already has a `@media (hover: none)` reset. Leave those alone.

- The chevron rotations in `CompatCard`, `ProductAccordionCard` and `ProductDetails`.

- Every `@keyframes`, `.reveal*`, `[data-reveal]`, `Collapse`, `.drop`, `Sheet` and `Snackbar` motion, and the calendar's landing entries.
